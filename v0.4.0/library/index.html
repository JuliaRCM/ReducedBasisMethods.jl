ReducedBasisMethods.ReducedBasis — Type
ReducedBasis{DT, ALG, PAR, PS, ΨT}

A reduced basis of element type DT, built by the algorithm algorithm.

The fields are

  • algorithm: the tag that built the basis;
  • parameters and paramspace: what the basis belongs to, and where the tolerance that chose k can be recorded;
  • Λ: the full spectrum, sorted descending and with its negative entries kept, so that a caller can plot it;
  • k: the basis size, size(Φ, 2), which the constructor sets;
  • Φ: the N × k basis for POD, and the N × k real factor of the basis otherwise;
  • Ψ: the imaginary part Im U of the singular vectors whose real part is Φ, for ComplexSVD, and nothing for every other algorithm.

Matrix(b) assembles Φ for the POD algorithms, diag(Φ, Φ) for the cotangent lift and [Φ −Ψ; Ψ Φ] for the complex SVD. Ψ is a type parameter, so the field costs nothing for an algorithm that does not use it.

ReducedBasisMethods.ReducedBasis — Method
ReducedBasis(algorithm, S, parameters, paramspace; k = nothing, tolerance = nothing)

The reduced basis of the real snapshot matrix S, built by algorithm.

S is the N × m snapshot for PODSVD and PODEVD, and the stacked 2N × m matrix [Q; P] for CotangentLiftSVD, CotangentLiftEVD and ComplexSVD. Its element type is Float32 or Float64, the real types LAPACK computes in, and the basis has the same element type.

Exactly one of k and tolerance says how large the basis is. k counts the retained columns of Φ (and of Φ + iΨ for ComplexSVD); a PSD basis assembles 2k columns. tolerance keeps the leading factors that carry all but tolerance of the energy sum(max.(Λ, 0)).

Throws an ArgumentError, before any decomposition, when S has a zero dimension, when a PSD snapshot has an odd number of rows, when k is outside 1:kmax, where kmax = min(N, m) for the POD and complex algorithms and min(N, 2m) for the cotangent lift, when tolerance is outside [0, 1), when both or neither of k and tolerance are given, and when S has a NaN or an infinite entry.

ReducedBasisMethods.ReducedTensor — Type
ReducedTensor(tensor::GridTensor{DT, 3}, Pi::AbstractMatrix, Pj::AbstractMatrix)

The lazy size(Pi, 2) × size(Pj, 2) × size(tensor, 3) array that projects the first two indices of the rank-3 GridTensor tensor onto the columns of Pi and Pj: rt[i, j, k] is tensor[m, n, k] * Pi[m, i] * Pj[n, j] summed over the tensor's entries.

The sum follows the tensor's locality contract. With S(m) the periodic stencil of the tensor's own width that stencil_indices(tensor, m) returns, tensor[m, n, k] is nonzero only where n ∈ S(m) and k ∈ S(m). The stencil is symmetric, k ∈ S(m) exactly where m ∈ S(k), so

\[rt[i, j, k] = \sum_{m ∈ S(k)} \sum_{n ∈ S(m)} tensor[m, n, k] \, Pi[m, i] \, Pj[n, j] .\]

The contract is what this type assumes of the tensor and never checks: a check would read every entry.

Every direction of the grid needs at least 2w + 1 nodes for the stencil width w, or the stencil names a node twice and the constructor throws an ArgumentError. Pi and Pj need size(tensor, 1) and size(tensor, 2) rows, or the constructor throws a DimensionMismatch, and their element type has to be DT, or it throws an ArgumentError. An index off the array throws a BoundsError. The projections are one-based; offset axes are neither checked nor claimed.

julia> using MultiIndexArrays: GridTensor, MultiIndexLazyArray

julia> gt = GridTensor(MultiIndexLazyArray(Float64, (I, J, K) -> 1.0,
           (3, 3), (3, 3), (3, 3)), 1);   # the width-1 stencil covers the 3 × 3 grid

julia> rt = ReducedTensor(gt, ones(9, 2), ones(9, 1));

julia> size(rt)
(2, 1, 9)

ReducedBasisMethods.SymplecticDEIM — Type
SymplecticDEIM(A, L, U, stencil, h, ∇h)

Structure-preserving DEIM for a Hamiltonian H(x) = ½xᵀLx + Σᵢ hᵢ(x), after Peng and Mohseni, doi:10.1137/140978922.

DEIM is applied to the densities hᵢ, not to the gradient ∇H, and the reduced gradient is then obtained by differentiating the reduced Hamiltonian exactly. The reduced gradient is therefore the gradient of a scalar, and its Jacobian is symmetric by construction. In contrast, the plain DEIM reduction of eq. (5.8) of the same paper uses W = AᵀΨ(ΠᵀΨ)⁻¹ and does not guarantee a symmetric reduced-gradient Jacobian or a Hamiltonian reduced system.

Arguments

  • A: an N × r basis. It need not be symplectic: H̃ is defined for any A.
  • L: the N × N matrix of the quadratic part. Only its symmetric part enters H̃, which is exact, because ½xᵀLx = ½xᵀ·sym(L)·x.
  • U: an M × m orthonormal basis of density snapshots, where M is the number of densities.
  • stencil(i): the indices of x that the density hᵢ reads, as any 1-based AbstractVector{<:Integer}.
  • h(xs, i): the scalar hᵢ at the values xs of its stencil. xs is a lazy view of A[stencil(i), :] * z, which allocates nothing.
  • ∇h(xs, i): the gradient of hᵢ with respect to xs, as any indexable collection — a Vector or a Tuple.

The element type is T = float(promote_type(eltype(A), eltype(L), eltype(U))). L̃ and the weights are stored in T, and A is stored as passed. The call of the returned object and hamiltonian_gradient! are generic over eltype(z), with no typed internal buffer, so ForwardDiff dual numbers pass through them; inputs mixed between two element types are not supported.

Throws an ArgumentError where m > M, and for a column of the density basis U whose largest DEIM residual magnitude ρ is not both positive and finite: ρ == 0 where the column is zero or exactly dependent on the ones before it, and ρ is NaN or Inf where the column holds a NaN or an Inf. get_DEIM_indices is the check.

ReducedBasisMethods.SymplecticDEIM — Method
(sd::SymplecticDEIM)(z)

The reduced Hamiltonian H̃(z) = ½zᵀL̃z + Σⱼ wⱼ h_{pⱼ}(A_{Sⱼ}z), where Sⱼ = stencil(pⱼ) and A_{Sⱼ} = A[Sⱼ, :]. Its gradient is hamiltonian_gradient!, and H̃ is an exact invariant of ż = J₂ₖ∇H̃(z), after Peng and Mohseni, doi:10.1137/140978922.

The call allocates nothing of its own: h receives a lazy view of A_{Sⱼ}z, so where stencil and h allocate nothing the call reads 0 B, and anything a callback allocates is the caller's. A NaN or an Inf in z, or from h, enters H̃ with no check.

ReducedBasisMethods._ReducedVectorField — Type
_ReducedVectorField{F, BT, T, H} <: Function

The vector field of an emitted reduced problem, in the form F ∈ (_ODEForm, _VelocityForm, _ForceForm).

It holds the basis BT — a ReducedBasis, or the SymplecticDEIM whose system is already in reduced coordinates — the gradient ∇H!(g, t, x, params) as the type parameter H, and its work buffers: x = A·z and g = ∇H(x) in the basis's element type T, which are distinct because ∇H! may read x after it writes g. ReducedBasisMethods._basis_size — Function
_basis_size(Λ, k, tolerance, kmax = length(Λ))

The basis size: k as an Int when it is given, and otherwise the energy rule on the spectrum Λ, at most kmax. The constructor has checked both keywords.

The energy Λ⁺ = max.(Λ, 0) is accumulated, and the first of the leading kmax indices whose running sum reaches (1 - tolerance) of the whole energy is kept, or kmax if none does. The clamp is what makes a negative entry, which a Gram matrix of a rank-deficient snapshot produces, contribute no energy. The last index of Λ always qualifies for finite cumulative energy, so the rule never runs past the spectrum, even at tolerance = 0; the constructor refuses a non-finite snapshot, so the energy is finite.

ReducedBasisMethods._reduce — Method
_reduce(::Union{PODSVD, CotangentLiftSVD, ComplexSVD}, S, parameters, paramspace, k, tolerance)

The basis from the thin SVD of S for PODSVD, of [Q P] for CotangentLiftSVD and of the complex C = Q + iP for ComplexSVD, where S = [Q; P]. Its spectrum is Λ = σ², and the basis is built from the first k left singular vectors U: Φ = U for POD and the cotangent lift, so that the cotangent-lift basis is diag(Φ, Φ), and Φ = Re U, Ψ = Im U for the complex SVD, so that its basis is [Φ −Ψ; Ψ Φ] and the lift of [a; b] is U(a + ib).

The imaginary part is imag(U) and never conj(U): a basis built from conj(U) is symplectic too, but it spans X − iV.

LAPACK's gesvd! runs with jobu = 'S' and jobvt = 'N'. The right factor is not formed because no basis uses it, and for the snapshot matrices this package reduces it costs as much memory as the snapshot itself.

ReducedBasisMethods._reduce — Method
_reduce(::Union{PODEVD, CotangentLiftEVD}, S, parameters, paramspace, k, tolerance)

The basis from the eigendecomposition of the Gram matrix MᵀM of M = _left_matrix(S): the m × m matrix SᵀS for PODEVD, and the 2m × 2m Gram matrix of [Q P], up to a permutation, for CotangentLiftEVD, where S = [Q; P].

The spectrum is the whole Gram spectrum, σ² with the round-off eigenvalues of both signs kept, sorted descending by value, never by magnitude: |λ| would put the round-off eigenvalues of a rank-deficient snapshot among the leading ones. It is stored as it is, so a caller that plots it sees every eigenvalue of MᵀM. The basis is cut to kmax = min(size(M)...) entries, the most M admits.

Φ is the thin Householder Q of M·Ω[:, 1:k], where Ω holds the sorted eigenvectors. Its columns are orthonormal even where M·Ω[:, 1:k] loses rank, and no division by a round-off eigenvalue is needed. For each full-rank leading block of M·Ω, the first j columns of Φ span that block; at rank loss, Φ completes an orthonormal basis, so its projector can include directions outside the column space of M.

The Gram matrix squares the snapshot entries and can overflow for large finite inputs.

ReducedBasisMethods.get_DEIM_indices — Method
get_DEIM_indices(Ψ)

Returns the k rows that the greedy DEIM algorithm (Algorithm 1 of doi:10.1137/090766498) selects on the basis Ψ, whose N × k columns are the basis vectors.

This is the index form of get_DEIM_interpolation_matrix: for p = get_DEIM_indices(Ψ) and Π = get_DEIM_interpolation_matrix(Ψ), Π' * A == A[p, :] for every finite N-row matrix A, so A[p, :] evaluates Π' * A without forming Π.

The index of column i is the row of the largest magnitude of the residual r = Ψ[:, i] - Ψ[:, 1:i-1] * c, where c solves the interpolation problem of the columns selected so far. The residual of column 1 is the column itself. The magnitude decides, so a residual that peaks at a negative entry selects that entry; ties go to the first index.

Throws an ArgumentError where k > N, and for a column whose largest residual magnitude ρ is not both positive and finite — ρ == 0 for a zero column or one exactly dependent on the ones before it, and NaN or Inf for a NaN or an Inf in Ψ. Every entry of a column enters that column's residual, so the test of each column covers the whole matrix.

source
ReducedBasisMethods.get_DEIM_interpolation_matrix — Method
get_DEIM_interpolation_matrix(Ψ)

Calculates the DEIM interpolation matrix as described in Algorithm 1 in doi:10.1137/090766498 to cheaply evaluate f(x).

The input matrix Ψ holds the eigenvectors of the snapshot matrix fᵢ(xⱼ), 1 ≤ i ≤ N, 1 ≤ j ≤ k. Returns the N × k matrix Π whose column i is the unit vector of the row that get_DEIM_indices selects for that column, so that f(x) ≈ Ψ * inv(Π' * Ψ) * Π' * f(x).

Its element type is float(eltype(Ψ)), so a Float32 basis gives a Float32 interpolation matrix. The selection, and with it the ArgumentError for k > N and for a column whose largest residual magnitude is not finite and positive, is get_DEIM_indices's.

julia> using ReducedBasisMethods

julia> get_DEIM_interpolation_matrix([1 1; 2 -1])
2×2 Matrix{Float64}:
 0.0  1.0
 1.0  0.0

ReducedBasisMethods.hamiltonian_gradient! — Method
hamiltonian_gradient!(g, sd::SymplecticDEIM, z)

Writes ∇H̃(z) = L̃z + Σⱼ wⱼ A_{Sⱼ}ᵀ ∇h_{pⱼ}(A_{Sⱼ}z) into g, after Peng and Mohseni, doi:10.1137/140978922. Its Jacobian, L̃ + Σⱼ wⱼ A_{Sⱼ}ᵀ ∇²h_{pⱼ}(A_{Sⱼ}z) A_{Sⱼ}, is symmetric by construction, so H̃ of SymplecticDEIM is an exact invariant of ż = J₂ₖ∇H̃(z).

The write allocates nothing of its own: ∇h receives a lazy view of A_{Sⱼ}z and may return any indexable collection, a Vector or a Tuple, so where stencil and ∇h allocate nothing the write reads 0 B, and anything a callback allocates is the caller's.

The write gives no guarantee for an aliased array: g and z must be distinct, because the quadratic part is written with mul!, which requires its output and its input to differ.

The constructor validates the density basis through get_DEIM_indices: m > M, and a column whose largest DEIM residual magnitude is zero or non-finite, raise ArgumentError. This write propagates errors from array operations and callbacks. A NaN or an Inf in z, or from ∇h, enters g with no check.

ReducedBasisMethods.reduced_ode — Method
reduced_ode(b::ReducedBasis, ∇H!, timespan, timestep, z₀; parameters = NullParameters())
reduced_ode(sd::SymplecticDEIM, timespan, timestep, z₀)

The ODEProblem of the reduced equation that the basis b carries, or of the hyper-reduced system sd, with the state z in reduced coordinates. Integration is the caller's: emit the problem, then hand it to an integrator of the caller's own.

For CotangentLiftSVD, CotangentLiftEVD and ComplexSVD the vector field is

\[\dot z = J_k A^{\mathsf T} ∇H(Az) ,\]

where A = Matrix(b) and J_k = [0 I_k; -I_k 0]. For PODSVD and PODEVD it is the Galerkin form

\[\dot z = U^{\mathsf T} J_N ∇H(Uz) , \qquad U = Φ ,\]

with J_N = [0 I_N; -I_N 0], where Φ has 2N rows. A POD basis forms no canonical symplectic matrix in its reduced coordinates, so its reduced dimension k may be odd. A SymplecticDEIM emits ż = J_2k ∇H̃(z) through hamiltonian_gradient!, which is the gradient of its own reduced Hamiltonian.

∇H! is the caller's gradient of the Hamiltonian, in the argument order of a vector field: ∇H!(g, t, x, params) writes ∇H(x) into g, and may read x while it writes g. params is the parameters keyword, passed through unchanged. No H is passed and no invariant is carried, so the caller measures H. The SymplecticDEIM method takes no ∇H!, because its reduced gradient is the system's own.

z₀ is in reduced coordinates, of length 2k for a symplectic basis — two blocks of k, the second starting at z₀[k + 1] — and of length k for a POD basis. Call project(b, x₀) to get it. Its element type is the basis's.

Throws

  • ArgumentError if eltype(z₀) is not the basis's element type; if a POD basis has an odd number of rows, where no split into two halves exists; and if a DEIM basis has an odd number of columns, for the same reason.
  • DimensionMismatch if length(z₀) is not the length above. Without it the blockwise lift ignores a surplus entry.

Cost

A vector field call allocates 0 B, after its first call for each state element type, which takes one pair of buffers from a per-type cache. The buffers and the basis are held by the emitted callable, and ∇H! is a type parameter, so the call is inferred and statically dispatched. What ∇H! allocates is not the callable's: a callback's allocations are the caller's. Emission itself allocates — it builds the callable, its buffers and the problem.

Concurrency

The work buffers belong to the emitted problem, so one problem is not safe to integrate from two tasks at once. Emit one problem per task.

Example

oscillator!(g, t, x, params) = (g .= x)          # H(x) = ½ xᵀx
b = ReducedBasis(CotangentLiftSVD(), S, NamedTuple(), paramspace; k = 10)
z₀ = project(b, x₀)
prob = reduced_ode(b, oscillator!, (0.0, 100.0), 0.01, z₀)
sol = integrate(prob, ImplicitMidpoint())

ReducedBasisMethods.reduced_pode — Method
reduced_pode(b::ReducedBasis{<:Any, <:SymplecticAlgorithm}, ∇H!, timespan, timestep, z₀; parameters = NullParameters())
reduced_pode(sd::SymplecticDEIM, timespan, timestep, z₀)

The PODEProblem of the split reduced equation: q̇ = v(t, q, p) is the first k rows of the symplectic form of reduced_ode and ṗ = f(t, q, p) is the last k, at the same point A·[q; p]. The initial conditions are the two halves of z₀, so the problem starts at (z₀[1:k], z₀[k + 1:2k]).

For CotangentLiftSVD, CotangentLiftEVD and ComplexSVD, whose assembly is A = Matrix(b), the two halves are the two halves of

\[\dot z = J_k A^{\mathsf T} ∇H(Az) , \qquad J_k = [0 I_k; -I_k 0] .\]

A SymplecticDEIM splits ż = J_2k ∇H̃(z) the same way, through hamiltonian_gradient!. PODSVD and PODEVD have no method at all: the coordinates of a POD basis have no q and p halves to split.

∇H!(g, t, x, params) is the caller's gradient of the Hamiltonian, writing ∇H(x) into g, and parameters is where params comes from — both exactly as for reduced_ode. The SymplecticDEIM method takes no ∇H!, and its two halves are the halves of J_2k ∇H̃(z).

Throws

As for reduced_ode: ArgumentError on a state whose element type is not the basis's, and DimensionMismatch on a state that is not 2k long. A PODSVD or PODEVD basis is a MethodError.

Cost

Each of v and f is a callable with its own buffers, and each allocates 0 B after its first call for each state element type, which takes a pair from that callable's per-type cache. What ∇H! allocates is not the callable's: a callback's allocations are the caller's. Emission allocates.

Concurrency

The two callables each hold their buffers, so one problem is not safe to integrate from two tasks at once. Emit one problem per task.

Example

oscillator!(g, t, x, params) = (g .= x)          # H(x) = ½ xᵀx
b = ReducedBasis(CotangentLiftSVD(), S, NamedTuple(), paramspace; k = 10)
z₀ = project(b, x₀)
prob = reduced_pode(b, oscillator!, (0.0, 100.0), 0.01, z₀)
sol = integrate(prob, ImplicitMidpoint())

ReducedBasisMethods.spectrumplot — Function
spectrumplot(σ::AbstractVector{<:Real}; title = "", ylabel = "", size = (620, 380))

Draw the spectrum σ of a reduced basis against its index on a log-scaled axis, in Float64. The values are drawn as given: singular values, or the squared singular values (Gram eigenvalues) that a ReducedBasis stores in Λ. ylabel names which, and size is the figure size.

Returns a Makie.FigureAxisPlot. Defined in a package extension that loads with Makie; save needs a backend such as CairoMakie.

ReducedComplexityModeling.project — Method
project(b::ReducedBasis, x)

The reduced coordinates of x in the basis b, for a vector or a matrix of snapshots.

The map is the symplectic inverse A⁺ of the assembled A = Matrix(b) for the two PSD structures and Φᵀ for the POD ones:

  • POD: Φᵀx;
  • cotangent lift: [Φᵀq; Φᵀp] with x = [q; p];
  • complex SVD: [Φᵀq + Ψᵀp; Φᵀp - Ψᵀq] with x = [q; p].

For both PSD structures A commutes with J (J_N A = A J_k), so A⁺ = J_kᵀAᵀJ_N = Aᵀ, which the tests assert against a dense J. Aᵀ is applied blockwise, and neither A nor J is formed.

The two PSD structures read x through views, so a call allocates the result and k-row temporaries, and nothing proportional to the number of rows of x.

project is ReducedComplexityModeling.project: this package imports the generic and adds a method, so a caller that loads both packages sees one name.
